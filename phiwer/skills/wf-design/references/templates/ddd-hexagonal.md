# Design doc template: DDD / hexagonal backend

**Only for backends built with Domain-Driven Design and a hexagonal (ports and adapters)
architecture**: a domain model with aggregates and invariants, application services that talk
to the outside world only through ports, and adapters that translate. If the project does not
have aggregates, ports and a dependency rule that keeps the domain free of infrastructure, use
the `default` template instead; these sections would only invite the implementer to invent
structure the codebase does not have.

It is the default template plus sections for domain language, the aggregate model and its
invariants, the consistency and transaction boundary, ports, and failure semantics. Selected
with `"designTemplate": "ddd-hexagonal"` in `.claude/workflow/project-config.json`.

Keep the frontmatter, Gates, Alternatives, Implementation (table and chunk progress) and
As-built: /wf-design, /wf-build and /wf-close depend on them.

Copy the block below into `{specDir}/{prefix}/{ticket-lower}-{short-name}.md`. Create it with
headings only at the start of planning and fill it in as decisions are made. Write for a reader
with no access to the planning conversation. Delete every section marked *(if applicable)* that
does not apply; an empty heading invites the implementer to invent content.

The project's own conventions (package layout, test infrastructure, architecture tests, commit
rules) live in `CLAUDE.md` and `.claude/rules/`, and the design must respect them without
restating them here.
